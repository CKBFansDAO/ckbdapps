# What it proves

A Tornado Cash-style anonymity pool fits inside CKB's cycle budget. Each withdrawal verifies a Groth16/BN254 proof plus a 256-level nullifier set in about 69.4M cycles locally (about 2% of a block's 3.5G limit), and about 102.5M cycles for the smaller size build actually deployed on the public testnet. The pool keeps no Merkle tree on-chain: its entire state is 1,640 bytes in one cell. A withdrawal transaction has a single input, the pool cell, and no signature; the circuit binds the recipient and fee, so nobody can front-run a proof and change where the money goes. Pool v2 adds deposit-intent cells and batch settlement behind a Type ID: a depositor can leave after funding an intent, and anyone can bundle intents and withdrawals into one transaction. On testnet the largest batch settled 20 withdrawals in 2.05 billion cycles (59% of the block limit).

# How it uses CKB

One pool is one cell that is never destroyed: a pool type script holds a depth-20 Poseidon commitment tree as 30 recent roots plus a frontier, and a sparse Merkle tree root for spent nullifiers, while a keyless pool lock means nobody can freeze the pool. The on-chain scripts are written in Rust for CKB-VM and share their core logic with the prover through no_std crates. The web demo connects a wallet with the official CCC connector, generates note secrets and withdrawal proofs in the browser via WebAssembly built from the same crates, and talks directly to a public testnet node with no backend of its own. A Cloudflare Worker acts as the aggregator, batching intents and withdrawals and paying the miner fee; if it ignores you, a self-send fallback broadcasts a signature-free single withdrawal. Both the page and the worker replay every pool transaction from the creation transaction and refuse to work unless the result matches the on-chain cell byte for byte.

# Before mainnet

It runs on CKB testnet only, and the repository has no license yet (the README calls it internal research). The Groth16 trusted setup is dev-only, generated by one person with the toxic waste still on that machine, so a real deployment needs an MPC ceremony or a universal setup; the groth16-ckb verifier and the contracts are unaudited. The circuit binds only 31 of the 32 bytes of the recipient lock hash, there is no domain separation, and v1 pools have no Type ID, so lookalike pools with smaller anonymity sets are possible (v2 fixes this). Deployment locks 141k–297k CKB of capacity for the scripts and verification key, shared by all pools, plus 1,819 CKB per pool. The aggregator is a single-machine demo with no relayer guarantees, and the root history covers only 30 deposit transactions in v1.
